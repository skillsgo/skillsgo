# Hub Catalog Module
> F3 | Parent: `/hub/AGENTS.md` | Workspace: `github.com/skillsgo/skillsgo/hub`

## Members

- `catalog.go`: exposes the Catalog API, reusable Package Version aggregate validation, transactionally serialized effective/equivalent Version publication with current recomputation after every observed-Version write, ordered current-Package update projections, independently constructible business/extension-schema-fixed zero-minimum PostgreSQL pgx pools with bounded idle retention and verified search paths, content-addressed global localization success/failure identity, bounded missing-or-stale translation candidates, one-query localized Skill-card read models, ID-keyset due Repository metadata selection, and ordered Skill membership with persisted source-language provenance.
- `backfill.go`: owns durable Package Backfill Run business state, active-work deduplication, heartbeat recovery for running work, River-aware orphan reconciliation candidates for queued work, explicit per-Version outcomes and aggregate counts, retry-safe outcome replacement, terminal failure codes, exact-publication commit checks, and atomic PostgreSQL Run-plus-River enqueue scopes.
- `migrations.go`: installs and verifies PostgreSQL extension prerequisites in the configured extension schema, executes embedded checksummed Atlas SQL migrations in the configured application schema, and serializes migration runs.
- `migrations/postgres/`: contains the reviewed, checksummed Atlas migration history, including content-addressed effective Versions, artifact-free equivalent observed Versions, complete effective-Version membership and source-language provenance, Backfill Run aggregates and per-Version outcomes, Package metadata, presentation localization outcomes, and PostgreSQL search resources.
- `queries/`: contains the maintained sqlc query source, including set-based localized card hydration, current-Package update hydration, and due Repository metadata keyset scans; SQL used by Catalog business operations belongs here except connection-scoped PostgreSQL advisory locks.
- `catalogsqlc/`: contains reproducible sqlc-generated pgx/v5 query code and must not be edited manually.
- `catalog_test.go`, `postgres_integration_test.go`: specify the zero-minimum pool policy and PostgreSQL behavior contract with Testcontainers, including the three-table baseline, Package Path plus Skill Name aggregation coordinates, path-unique same-name snapshots, deterministic name-query defaults, immutable Version ownership, historical membership, current projection, bounded translation candidates, terminal-failure suppression with prompt-version renewal, Find ordering/fields, and pagination.
- `postgres_integration_test.go`: verifies Package Version publication and current-member lookup against real PostgreSQL.

## Architectural Boundary

This module owns searchable public Skill metadata, immutable observed Package Version records and effective-Version membership, provider-neutral Package metadata cache state, globally deduplicated presentation localization outcomes keyed by source digest, and schema evolution. `packages`, `versions`, and effective-version-owned `skills` are the three core identity tables. An effective Version owns an Artifact and coordinate-bound Sum; an equivalent observed Version points directly to an effective Version with the same version-independent content Sum and owns neither. A Package stores its canonical Path, Source Host, and host-relative Source Path; cross-entity projections expose that identity as Package Path. Package is the version and artifact boundary; a Skill snapshot belongs to one effective Version but has no independent version, Sum, ZIP, licensing metadata, or publication lifecycle. PostgreSQL Atlas migrations are the schema source of truth, sqlc queries are the maintained data-access source, and pgx is the only runtime database interface. The configured business schema owns Catalog, River, and migration-history tables; `pg_trgm` lives in the independently configured extension schema. Every pool binds and verifies the same ordered business/extension search path. Online Catalog work uses the foreground pool while River and its handlers use the background pool. Atomic business-state-plus-job submission uses one caller-owned transaction from the background pool. It must not own install events, aggregate rankings, artifact bytes, HTTP rendering, local installation inspection, or App presentation concepts.
