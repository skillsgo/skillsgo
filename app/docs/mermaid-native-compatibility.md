# Native Mermaid Compatibility

SkillsGo targets the official Mermaid 11.16.0 grammar at commit
`7c0cafcf42e76bfaf79d0cbbd12edb986612f014`. The reference checkout is
`/Users/freeman/Documents/Codes/mermaid`. Production rendering remains pure
Dart and Flutter Canvas; JavaScript, WebView, remote rendering, and runtime
network access are prohibited.

Compatibility is proven per syntax feature, not merely by recognizing a
diagram header. A type is complete only when its official parser fixtures,
layout behavior, theme behavior, and representative render cases pass native
tests. Until then, unsupported input must remain visible as selectable source.

The hermetic documentation corpus at
`test/fixtures/mermaid/official_syntax_examples_11_16_0.json` contains 418
complete diagrams extracted from every official 11.16.0 syntax page. The
corpus is regenerated by `tool/update_mermaid_official_fixtures.dart`; its
native parser gate is `test/mermaid_official_audit_test.dart`.

Leading YAML frontmatter now passes through one shared native preprocessor.
It matches Mermaid's indentation and delimiter rules, applies `title` and
`displayMode`, retains the complete nested `config` tree without discarding
unknown keys, and rejects malformed YAML. Every official diagram-specific
renderer field represented in the matrix below is routed into native parsing,
layout, interaction, or Canvas painting; preservation alone is not counted as
rendered parameter compatibility.

## Completion Gates

1. Every official detector maps to a native type.
2. Every official parser fixture is classified and has an equivalent native
   acceptance or intentional security restriction.
3. Every admitted syntax construct is represented without silently dropping
   semantics.
4. Every type has deterministic Light and Dark render tests.
5. Large official examples meet bounded parse and layout performance tests.
6. Unsupported or invalid input always falls back to selectable source.
7. `flutter analyze`, the complete App test suite, and a macOS build pass.
